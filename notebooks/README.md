# Workflow notebooks (Reynolds Creek example)

Three notebooks that walk through the workflow on one example day (18 March 2019), saved with their outputs:

| notebook | what it shows |
|---|---|
| `01_preprocessing.ipynb` | the 30 m grid and static layers, daily MODIS snow fraction (MOD10A1F), a Landsat 8 snow map, and the snow-persistence ranking |
| `02_downscaling.ipynb` | MODIS fraction to 30 m snow cover step by step, a score against the same-day Landsat map for three rankings, pixel seams, and snow-on/off dates for one cell |
| `03_verification.ipynb` | ARS snow depth: one site and winter, melt-out at all sites and years, day-by-day agreement; split-year cross-validation against Landsat and Sentinel-2 |

Run them in order from this folder (`jupyter lab`, or `jupyter nbconvert --to notebook --execute --inplace 0*.ipynb`). They read the released files one level up and the code in `../code/`.

- Python packages: numpy, pandas, matplotlib, netCDF4, numba, rasterio, pyproj, scipy (see `requirements.txt`).
- Notebook 1 downloads one Landsat scene from Microsoft Planetary Computer on its first run and caches it in `data/`; the cached copy is included, so no network is needed.
- Notebook 3 reads the ARS snow depth record from `../../ground/rcew_ars/`. That record belongs to USDA-ARS (Andrew Hedrick) and is not part of the snow-cover release unless ARS agrees.
- The daily file may be one NetCDF or four parts along time; `../code/daily_io.py` reads either.
- The notebooks are generated by `../code/make_notebooks.py`. Edit that script, not the notebooks, to keep the two in step.
